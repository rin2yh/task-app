# TypeScript ルール

TypeScript コードを書く / 整理するときの方針。新しい方針が必要になったらこのファイルにセクションを追加する。

## `types.ts` を作らない

型を集めるだけのファイル (`types.ts`, `interfaces.ts` など) を**新規作成しない**。

- 型は、その型を返す / 使う関数・クラスと同じファイルに置く。
- 複数モジュールから参照される型は、定義しているモジュールの責務名で `.ts` に置き、利用側は `import type` で取る (例: OAuth クライアント契約は `oauth/client.ts`、`oauth/types.ts` ではない)。
- 既存の `types.ts` を見つけたら振り分ける。

### 理由

- 「型かそれ以外か」でファイルを切ると、振る舞いと契約が引き剥がされ、ファイル名から責務が読み取れなくなる。
- 型の移動だけで意味が変わらない再構成 (`types.ts` ↔ `*.ts`) を誘発し、history が散らかる。

### 例外

- スキーマ生成 (Drizzle の `server/db/schema.ts` 等) のようにツール / 規約上ファイル名が固定されている場合は従う。
- 外部由来の型を集約する宣言ファイル (`*.d.ts`、`global.d.ts`) は対象外。
